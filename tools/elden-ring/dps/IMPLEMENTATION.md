# 連続DPS機能：実装前仕様

2026-10-02。PR #24の既存候補データに、時間の根拠・限定的な周期モデル・接続仕様を追加した。画面改修の実装を追加済み。公開前のPRで確認する。

## 準備状態

- データ参照：701エンティティ、1,189プロファイルを読み込める。
- 時間基準：Frame Data Explorer自身の表示コードが30資料フレーム＝1秒と扱うことを確認。取得済みJSと現在の配信JSはSHA-256一致。
- vDex境界：取得元の10〜70補間と半フレーム単位の切上げを独立関数にしてテスト済み。
- 通常攻撃：1.17対応の公開HKSにある連撃数／分岐を参考に、86プロファイルの条件付きモデルを生成。
- 魔法：輝石のつぶての右手詠唱について、初回段と定常反復の分離、コンボ効果の分岐を整理。
- 未完：ゲーム内でのタイミング・入力受付・ヒットストップ・実ヒット数の照合。公開HKSはコミュニティ編集を含み、ゲーム本体との同一性を保証しない。

**コード・UIの実装に着手できる仕様は揃っている。正確なゲーム内DPSとして公開するための検証は残っている。** モデル値は `ranking_eligible=false` を維持する。初期UIは別指標「理論DPS・未実測」としてモデル値を比較できるようにし、実測済みDPSと混在させない。正確なゲーム内DPSとしての扱いには別の検証が必要。

## 初期計算条件を固定

初期値は、同じ敵へ同じ地上通常攻撃を途切れず繰り返す定常状態の理論DPS。FP・スタミナは十分にある前提。1回目だけの始動は定常周期に含めず、武器の最終段から初段に戻る時間は含める。反撃回避・聖杯瓶・状態異常発症・条件付きバフ・PvP・部位特効は範囲外として表示する。

防御前DPSと対敵DPSは異なるモードとする。対敵モードでは、各ヒット・各属性の防御計算を済ませてから周期合計を取る。「周期の攻撃力を合計して1回だけ防御計算」は禁止。

## 通常攻撃モデルの採用条件

`readiness.py` は次の全条件を満たすものだけを `model_candidate` にする。

1. 初期対応カテゴリの通常武器で、特殊カテゴリと対武器を除く。
2. HKSのカテゴリ別連撃数の各段に、対応するモーションが一意にある。
3. 各段は近接Attack窓1つ、対応攻撃参照1つ。投射物・固定攻撃成分・追加最終倍率なし。
4. 速度勾配なし。必要な段に欠落なし。
5. 次段の受入種別と一致するRegularキャンセル窓があり、攻撃窓の終端以前にキャンセルされない。

カテゴリ別の段数から最終段→初段までの環を作る。最短の適合キャンセル開始を遷移時刻とするのは**明示したモデル仮定**である。実入力のフレーム端・ブレンド・ヒットストップ等はまだ検証されていない。資料名だけで全モーションを足さず、攻撃窓のないR1 9等は正規コンボ段に含めない。

| 例 | モデル段数 | 周期（資料フレーム） | モデル秒数 | 検証状態 |
|---|---:|---:|---:|---|
| ロングソード片手 | 5 | 114 | 3.8 | 未実測 |
| ダガー片手 | 6 | 96 | 3.2 | 未実測 |
| 打刀片手 | 5 | 112 | 3.7333… | 未実測 |
| ロングソード両手 | — | — | — | 速度勾配があり初期モデル対象外 |

これらは性能の確定値ではなく、実装と検証に用いる具体的な予測値。テストが証明するのは資料からの変換とモデル内の整合性。

## 魔法の境界と連続詠唱

`castingBoundarySourceFrame([fast, slow], vDex)` は取得元の境界補間を再現する。vDexを10〜70に制限し、2倍したフレーム値で補間、切上げ、2で割る。例として `[17,22]` の境界はvDex10/40/70で22/19.5/17資料フレーム。

この関数は詠唱全体を一律短縮するものではない。初回詠唱段、連続詠唱段、詠唱速度が作用する窓を別々に扱う。装備由来の仮想技量を実装側が別途解決するまではvDexを明示入力する。

輝石のつぶて（右手）のレビュー候補は `045000 → 045010 → 045020 ⇄ 045030`。同じ魔法アニメーションを使い、効果100600/100601が有効な場合の分岐をHKSで確認した。ただしHKSイベントとモーションIDの対応、ブレンド、実機の周期は要検証。左手側は別効果であり、右手モデルを流用しない。弾の命中数・飛翔時間・二次効果を推測して合算しない。

## 既存コードへの接続箇所

| 箇所 | 変更内容 |
|---|---|
| `tools/elden-ring/engine.js` | 新しいDPS入口を追加。`weapon()`の属性攻撃力にヒットごとのMV/100を適用し、対敵時は各ヒットで`hitDamage()`を呼ぶ。魔法は解決済み成分だけを`spell()`で計算 |
| `tools/elden-ring/ui.js` | `weaponScore()`と魔法一覧のscore選択にDPSを追加。既存の成分単位魔法行をDPSでは行動単位へまとめ、別成分を別の魔法として順位付けしない |
| `tools/elden-ring/template.html` | ソート選択、攻撃方法、計算条件、周期・ヒット内訳・検証状態の表示 |
| `tools/build-elden-ring.mjs` | 必要なDPSデータと読込コードを単体HTMLへ埋込み。非同期読込完了前のDPSソートを無効化 |
| `tools/test-elden-ring-ui.cjs` | モバイル表示、ソート変更、能力変更での再計算、未対応末尾、保存／共有の回帰を追加 |

ARに含まれる蓄積値（5以降）を属性ダメージとして合算しない。物理属性のStandard等は既存敵テーブルのキーに明示変換し、未知属性を通常物理へ黙ってフォールバックさせない。既存 `hitDamage()` のフォールバック挙動をDPS入力の検証代わりにしない。

## 関数の入出力契約

入力は `profileId / variantId / stats / upgrade / handMode / catalystId / virtualDexterity / enemyId / ng / scadutree / manualMultiplier / scope / payloadHash / validationRevision`。魔法に不要な武器派生値等はnullとしてよいが、キャッシュキーには適用される値をすべて含める。

出力は `status / dps / cycleSeconds / cycleDamage / hits / conditions / reasons / provenance`。

- `status=ready`：検証済みプロファイルでのみ使用。有限・非負のDPSと正の周期を返す。
- `status=model_only`：明示された理論モデル指標でのみ比較し、モデル条件と未実測を表示。実測済みの順位には使わない。
- `status=unsupported`：DPSはnull、理由を返す。
- `status=unusable`：能力不足または触媒不適合。DPSはnull。
- `status=loading` / `error`：DPSはnull。旧条件のスコアを表示しない。

装備可否は従来の能力不足判定を先に適用する。両手の能力判定と対武器の例外も既存エンジンを使う。魔法触媒の自動選択は、DPSに含めた全成分と同じ条件で選び直す。

## ソート・表示・保存

- 検証済みDPSの降順。同点は安定したID順。未対応・未検証は末尾で「—」、0 DPSと混同しない。昇順でも未対応は末尾。
- 順位番号は計算可能な行だけに付け、対応件数/全件数を表示する。試験モデルと検証済みの順位表を混在させない。
- 片手／両手、敵、能力値、強化、触媒、vDex、加護、手動倍率の変更で再計算する。
- ARソートは継続して使えるようにし、対応プロファイル0件ならDPS項目を無効化して理由を表示する。
- 保存状態にDPSの選択条件を追加し、旧保存データには既存のARソートを既定値として補う。共有URL・JSON取り込みにも同じ検証を適用。
- 表示文：「連続DPS」「FP・スタミナが十分な場合」「使用攻撃：片手通常攻撃5段」「未対応：攻撃速度変化の検証待ち」。ソースコード上のIDを通常のユーザーフローへ出さない。

## 実装着手と公開の合格条件

実装着手に必要なデータ読込・型・接続先・出力契約・代表モデル・ソート規則は用意済み。

公開までには、代表モデルごとに `measurement-template.json` に版、条件、録画フレームレート、最終段→初段を含む反復測定、ヒット数、出典を登録する。空振りと命中で測定し、ゲームの描画FPSと資料の30fps基準を混同しない。測定誤差の根拠も記録し、モデルとの差が誤差範囲を超えるものは昇格させない。追加のアニメーション種・速度勾配・多段を、既存モデルのテスト結果だけで検証済みにしない。

公開時の検証済みデータは別形式とし、入力スナップショットSHAと検証記録の参照を必須にする。候補payloadやsidecarのbooleanを手編集して検証を省略しない。

## 実行

```bash
python tools/elden-ring/dps/readiness.py
python tools/elden-ring/dps/test-readiness.py
node tools/elden-ring/dps/test-timing-model.mjs
```

元データの参照整合性テスト・読込テストは前のREADME記載のコマンドを引き続き実行する。

## 初期UI実装の補足

通常攻撃モデルを `weaponDps()` から計算し、理論DPSの降順で表示する。未対応はnullとして末尾。計算時に全条件から再計算するため、初版はスコアキャッシュを設けない。魔法・戦技はモデル未解決のため、DPS選択を提供しない。ソート選択はsettings.weaponSortに保持し、旧保存値はtotalへ補完する。
