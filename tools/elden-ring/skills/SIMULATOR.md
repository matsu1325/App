# 戦技シミュレータの条件

収集済み1.17スナップショットを使い、武器ARから計算できる攻撃成分をシミュレートする。実機測定や最終式の全件検証を済ませたデータではない。収集台帳の `simulator_ready: false` は変更しない。

267候補を検索でき、全1,665資料動作を収録する。少なくとも1つの動作で全選択判定を試算できる候補141、一部成分のみ30、計算モデルなし96（効果・防御・移動系を含む）。171戦技すべての全動作・全段を計算できるという意味ではない。画面の計算対象は「選択した資料動作の、選択した各判定が1回命中する」という条件。

[全267候補の対応表](../../../data/elden-ring-skills/simulator-coverage.csv)は、武器候補・動作数・計算状態・入力FP対応数・欠落参照・未対応理由を機械可読で記録する。従来除外していた判定資料なし440動作も閲覧でき、キック等の攻撃参照不足と効果・移動の動作を区別する。既定武器に動作の対応資料がない場合も、資料名と未確認理由を確認できる。

## 計算

`compile-runtime.mjs` は元資料のSHA-256とサイズを照合し、武器ごとの攻撃参照を解決する。同一判定の完全一致エイリアスは1つだけ採用する。異なる攻撃候補・親子弾を勝手に合算しない。

モデルに採用するのは、元パラメータと生成表の属性別MV・固定値が一致し、攻撃参照と依存先が解決し、弾参照がなく、固定値が0で、独自補正・特殊攻撃処理・投げ／掴み・未確認の両手補正がない成分に限る。動作の欠落依存がダメージに無関係と確認できていない場合は、その動作を計算停止し、欠落参照を表示する。実機・入力・周期の未検証とは区別する。

1. ビルドの装備補正後能力値、武器・派生、強化、片手／両手から属性別ARを計算する。
2. 各判定の属性別MVをARに掛ける。影樹の加護・手動攻撃力倍率は防御前に掛ける。
3. 選択敵の防御・カット率を属性・判定ごとに適用してから合計する。物理属性も判定ごとに使う。

未計算の判定が残る場合、全体合計とFP効率を表示せず、計算できた成分の小計と理由を表示する。判定を外せば選択した成分だけの仮定を試せるが、全判定を選んでいない場合のFP効率は出さない。バフ専用戦技や未対応の攻撃を0ダメージとして扱わない。

月隠は刀身の特殊攻撃処理と親子弾の接続・独自式が未検証で、ダメージ合計は未計算。猛獅子斬りの追撃は未確認処理のある判定を除いた成分のみ試算できる。二連斬りなどの対応成分は判定ごとに防御を適用して合算する。

## 動作・FP・適合

居合、構え、獅子斬り、貫通突き、月隠、猛獅子斬りの一部動作は入力ラベルと基礎FPを対応付けた条件モデル。構えR1/R2、始動と追撃を分離する。残りFP0の枝は残り0を仮定するもので、残り1以上のFP不足時の消費・挙動を再現しない。実機入力の対応付けは未測定。

それ以外は資料の動作名を表示し、入力ごとの消費FPは未計算のままにする。利用者が仮定FPを指定した場合だけ効率を計算し、「仮定」と表示する。元パラメータのFP -1は不明扱い。装備によるFP軽減・追加入力を含むコンボ全体のFPは自動適用しない。

武器の既定戦技、参考適合表、武器の戦灰変更可否を照合する。参考表が欠くDLCなどは原戦灰のカテゴリ・派生フラグと当該武器の動作資料が揃う場合に候補とし、画面で「個別例外は未確認」と表示する。弓・調香瓶のように派生変更不可でも戦灰変更可能な武器は、元の派生・カテゴリ・戦灰の標準属性許可を照合する。固有武器の戦灰変更不可を無視しない。完全な装着可否を保証しない。

追加効果は候補の原値を閲覧できるだけで、発動・消費・重複を確認して自動適用したことにはならない。状態異常、爆発・独自弾、固有能力値補正、ヒット数の距離依存、部位・カウンター・PvP、周期・ヒットストップ・戦技DPSは未対応。資料フレームはDPSに変換しない。1.17.1差分と実機の最終ダメージは未検証。

## 保存・生成・検証

戦技ID、武器派生、動作、選択判定、仮定FPは既存のビルドJSONに `skillSimulation` として保存する。旧ビルドは既定選択に移行し、自動保存・名前付き保存・共有URL・取り消しに対応する。仮定FPは当該動作に限る。別戦技・別動作や未確認動作からの自動フォールバックでは解除し、同一動作の派生変更では保持する。右手1の既定戦技へ切り替える操作も解除対象。

```bash
# 収集スナップショットから再生成。未展開ならsnapshot.pyが復元する。
node tools/elden-ring/skills/compile-runtime.mjs
node tools/build-elden-ring.mjs
node tools/test-elden-ring-skills.cjs
node tools/test-elden-ring-skills-ui.cjs
```

圧縮ランタイムは `data/elden-ring-skills/runtime/manifest.json` と8個のbase64パーツに保存する。通常のHTMLビルドはこの小さな成果物だけを読み、パーツ・展開後データ・元スナップショット・武器データ・コンパイラ・対応表のハッシュを照合する。コンパイラが変更されたまま再生成し忘れた場合も停止する。大型原本の展開やPython・ネットワーク取得は不要。生成HTMLにすべて内蔵し、アプリ実行時にも追加データを取得しない。

数値テストは既知MV/FP定数、各段・属性の防御、能力不足、強化、持ち方、FP0、不適合、DLC候補、未対応を含む小計、独自弾の非合算、手動FP、旧保存互換を確認する。全267対応表を実エンジンの49,920動作×武器モデルと照合し、候補欠落・依存欠落・掴み・キック・固定派生戦灰を回帰確認する。UIは全267選択肢、FPの持ち越し防止と取り消し・やり直し・再読込、保存・共有、390/1440px、通信遮断時の単一HTML起動を確認する。破損・版不一致と隔離コピーでの完全再生成も確認する。これは実機精度の保証ではない。

```bash
node tools/test-elden-ring-skills-loader.mjs --regenerate
# 数値、原資料の復元・統合検証、再生成、3画面テストを順に実行
node tools/check-elden-ring.mjs
```

GitHubのPRでは `エルデンリング検証` を実行し、mainの公開処理も同じ検証の成功に依存する。公開処理は検証に失敗すれば配信前に停止する。1.17.1の差分、原TAEの不足、独自弾・固有式・バフ・DPS・実機測定の残課題と必要資料は [補完状況](REMAINING.md) に記録する。
