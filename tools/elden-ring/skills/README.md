## 参照の接続と注意点

```text
SwordArtsParamのRow ID: 100 / 101 / 114 / 115
  → swordArtsTypeNew:    0 /   1 /  14 /  15
  → HKSの arts_id + 600: a600 / a601 / a614 / a615
  → animationsの判定イベント
  → 武器別に1件を選ぶ加工攻撃キー
  → BehaviorParam_PCのrefId
  → AtkParam_Pcの行・属性別MV・補正フラグ
```

HKSの戦技番号とSwordArtsParamの行IDは同じではない。HKSの根拠は固定コミット`d88d6441f5fccfdd6a5fd10d493309b680181897`の`c0000.hks`：`IsStanceArts`（878行付近）、`GetSwordArtsRequestNew`（986行付近）、`SetSwordArtsPointInfo`（1028行付近）、通常戦技入力（2280行付近）、構えからのR1/R2（11503行付近）、武器種選択（25435行付近）。コミュニティ編集を含む資料であり、Havokの全セレクターを復元できたという意味ではない。

例：獅子斬りの加工キー`300000000:3970`は、攻撃パラメータ`300000000`を直接指さない。BehaviorParamの行`300000000`を経由して`300300820`へ接続する。文字列の先頭をそのまま攻撃IDと見なすと誤る。

同じ窓に並ぶ複数参照は武器別の候補として保持し、代表武器で必ず1件だけ選択する。構えの通常直剣と石鞘の剣には物理属性の違いがある。名前一致だけで候補を合算しない。

`FinalDamageRateParam`由来の倍率はPvP用。参考シート`Info!C6,L6`に適用範囲の根拠がある。今回のPvE用MV例に0.8を乗算していない。両手攻撃ボーナス無効フラグは原値を保持し、その名前だけから筋力1.5倍の扱いを決めない。状態異常、強靭削り、装備効果、能力不足の扱いも最終式の検証が必要。
